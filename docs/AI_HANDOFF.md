## 0.8.14 상세 분류 끌어서 정렬

- ↑ ↓ 버튼(categoryMove)을 없애고 CategoryDrag로 바꿨습니다. 행 왼쪽 44dp ≡ 손잡이는 바로, 이름 영역은 길게 눌러 끌기 시작합니다. 끄는 동안 행은 제자리에 두고 translationY만 바꾸며(터치 대상 행을 removeView하면 CANCEL이 오므로), 놓을 때 CategoryOrder.moveTo → CategoryStore.reorder로 한 번만 저장하고 목록을 다시 그립니다. 목록 끝 56dp에서 자동 스크롤합니다.
- 이름 TextView의 tooltip은 길게 누르기를 가로채므로 제거했습니다. TalkBack은 행의 사용자 정의 동작 ACTION_MOVE_UP/DOWN(0x7e0c0001/2)으로 한 칸씩 옮깁니다.
- CategoryStore.reorder는 현재 보이는 목록과 같은 이름 집합일 때만 저장합니다(CategoryOrder.reorder). 저장 형식 COR1·order_유형 키·DB5·백업 형식은 그대로입니다. move(±1)는 호환용으로 유지합니다.
- JVM: CategoryOrderTests 128개(기존 38 + 이동/검증 90). Android CategoryOrderChecks는 손잡이 터치 이벤트로 실제 끌기(-3/+3/0행)와 접근성 동작을 검사하도록 바꿨습니다. 실제 화면 좌표를 Android 입력 경로에 주입하는 검사로 바꿨고, 긴 이름·32개 분류의 자동 스크롤·취소·접근성 동작을 확인했습니다. 실행 수는 docs/DRAG_REORDER_VALIDATION.md를 따릅니다.

- 끝 위치의 중심이 같은 경우 한 칸 앞에 저장되는 문제와 긴 행의 양 끝 이동을 보정했습니다. 대화상자/행 분리 시 프레임·대기·애니메이션을 취소해 저장하지 않습니다.
- 원본 키를 유지합니다. 서명 비밀번호는 CHAGOK_KEYSTORE_PASSWORD 환경변수에서만 읽습니다. 키·비밀번호·원본 패치는 저장소와 Release에 넣지 않습니다.

## 0.8.13 상세 분류 순서

- CategoryStore가 기존 종류별 StringSet/삭제 목록에 order_유형 문자열(COR1)을 별도로 적용합니다. 저축회수는 저축을 공유하며 기본 목록은 기존 가나다순입니다. 사용자 순서 뒤에 새 참조 분류가 붙습니다.
- CategoryOrder는 순수 JVM 순서/코덱 로직입니다. 손상된 설정은 읽기에서 가나다순으로 대체하고 덮어쓰지 않습니다. move만 해당 유형의 순서 키를 저장합니다.
- MainActivity의 상세 분류 관리에 고정된 추가 버튼과 48dp ↑ ↓ 버튼을 추가했습니다. 관리 중에는 거래·계획 참조를 재사용하고 분류만 다시 그립니다.
- 현재 XLSX/ZIP은 순서 설정을 포함하지 않습니다. 전체 초기화는 category_choices 전체를 지우므로 순서도 삭제합니다. DB5·기존 장부/시각/ID/rowid·계획·생활비 선택·회계 합계를 유지합니다.
- CategoryOrderTests와 Android order/orderdark/orderreopen/orderbefore/orderupgrade를 확인합니다. 신규 권한·라이브러리는 없습니다.

## 0.8.12 시간 기록

- `Entry.time=HH:mm:ss`; 이전 생성자와 시간 없는 파일은 자정입니다. DB1~4→5는 기존 rowid/ID/거래 필드·feature_state·설정 보존 및 실패 롤백이 필수입니다.
- 새 초안은 현재 시각, 수정은 원래 시각을 유지합니다. 사진 기준 달력 다음 → 시계, 뒤로 → 달력, 최종 확인만 반영합니다. 초는 시계의 별도 버튼입니다.
- A~F 기존 엑셀 열 위치를 바꾸지 않고 G에 시간을 추가했습니다. SMV4/ZIP3이며 이전 코덱 읽기를 유지합니다. 자정 fingerprint는 기존과 같아야 합니다.
- `TimeTests`, Android `time/timebefore/timeupgrade/timedark`를 확인하세요. 실제 폰에 테스트를 실행하지 않습니다. 합계·원금 보호는 일자 기준으로 유지합니다. 새 권한·외부 라이브러리는 없습니다.
