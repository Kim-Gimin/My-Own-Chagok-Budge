# 데이터·백업·업데이트 안전성

앱은 기기 내부 SQLite DB(`chagok.db`, DB5)와 별도 환경설정/계획 상태를 사용합니다. 앱에 인터넷 권한을 추가하지 않았으며, 문서 선택기를 통해 사용자가 고른 위치에 파일을 저장·가져옵니다.

| 자료 | XLSX 전체 백업0.8.10 이상 | 계획 포함 ZIP |
|---|---|---|
| 거래·시각·ID·기초자산 | 포함 | 포함 |
| 예산·목표/반복/즐겨찾기/생활비 선택 | 포함 | 포함 |
| 해지·배분 연결 메타데이터 | 미포함 | 포함 |
| PIN/화면/글꼴/숨김 분류/분류 순서/알림 설정 | 미포함 | 미포함 |

- 0.8.14는 기존 COR1 분류 순서를 그대로 읽습니다. 드롭한 목록이 현재 목록과 같은 이름 집합인지 확인하고 한 번 저장하며, 취소·화면 종료는 저장하지 않습니다. 거래·계획·환경설정 보호를 우회하지 않습니다. 원본 서명은 유지하고 비밀번호는 빌드 프로세스 환경변수에서만 읽습니다.
- 0.8.13의 분류 순서는 category_choices의 별도 설정입니다. 거래·시각·DB 구조·계획·생활비 포함 여부를 바꾸지 않으며 앱 재실행 후에도 유지합니다. 전체 초기화는 순서 설정도 지웁니다. 현재 XLSX/ZIP은 화면/숨김 분류와 같이 순서를 보관하지 않습니다.
- DB1~4에서 DB5로 업데이트하면 기존 거래의 날짜·유형·금액·분류·메모·ID/rowid를 유지하며 시간만 00:00:00으로 채웁니다. 계획·기초자산·이동·설정은 유지합니다. 마이그레이션 도중 오류가 발생하면 SQLite 트랜잭션을 롤백합니다.
- 시간은 새 XLSX G열과 ZIP3에 저장합니다. 기존 시간 없는 양식/ZIP1·2는 자정으로 읽습니다. 시간 포함 자료는 0.8.12 이상에서 복원하세요. 이전 앱은 시간 열을 무시할 수 있으므로 구버전으로 내보냈다 가져오면 시간 정보가 유실될 수 있습니다. DB5로 올린 설치의 APK 다운그레이드는 지원하지 않습니다.
- 계획 XLSX는0.8.10 이상에서 복원합니다. 이전 앱은 계획 시트를 복원하지 않습니다. 월별 엑셀/빈 입력 양식은 계획 백업이 아닙니다.
- 가져오기는 기존 자료에 추가합니다. 고유ID와 중복 판정, 현재 계획/명시적 생활비 선택 우선 규칙을 유지합니다. 초기화 후에도 파일 내부의 동일 항목이 중복으로 판정될 수 있습니다.
- 오류·원금 부족·연결 충돌이 있으면 원자 저장/롤백을 사용합니다. 기존 불완전한 자료를 임의로 보정하지 않습니다.
- 기초자산은 기록 시작 전의 보유분이며, 같은 금액을 새 수입/저축으로 중복 기록하지 않습니다. 저축회수는 수입이 아닙니다. 만기 연결 내역은 이동 전체 수정으로 처리합니다.
- 0.8.9의 분류 정리는 분류 경계 공백만 정리하고 거래ID/rowid/나머지 필드를 유지하며, 실패 시 저널/롤백으로 복구합니다.
- 같은 패키지·기존 서명으로 업데이트합니다. 앱 삭제나 설정의 앱 전체 초기화는 내부 장부와 설정을 삭제합니다. 먼저 필요한 XLSX/ZIP을 앱 밖에 저장하세요.

이 Git 저장소에는 실제 개인 엑셀·ZIP·DB와 서명키가 없습니다. 소스 원본 ZIP도 키를 포함하므로 그대로 업로드하지 않았습니다. 키는 로컬 별도 보관하고, 앱 APK는 [버전 목록](RELEASES.md)에서 확인하세요.
