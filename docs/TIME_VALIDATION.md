# 기록 시각 검증 — 0.8.12 / 2026-11-20

JDK17, Java8 대상, Android API36로 빌드했습니다. 기존 0.8.11의 JVM1,103개와 빌드 통과를 확인한 뒤 작업했습니다. Android 실행은 API35 전용 에뮬레이터이며 실제 사용자 폰·장부·백업을 테스트에 사용하지 않았습니다.

## 핵심 검증

- DB1/2/3/4 → 5에서 원래 거래 필드·ID/rowid를 보존하고 00:00:00을 추가합니다. 기존 feature_state의 rowid·값을 보존합니다. 일부 이관 후 인덱스 생성 실패를 유도해 DB 버전·열·원본 거래까지 롤백되는 것을 확인했습니다.
- 0.8.11 APK에 기초자산·납입·해지 연결·생활비 분류·즐겨찾기·화면/분류/백업 설정을 합성 저장한 뒤, 같은 서명의 0.8.12를 `install -r`로 설치했습니다. 기존 필드/rowid·feature_state 원문·환경설정이 같고 모든 이전 기록 시각이 자정임을 비교했습니다.
- 달력 취소, 시계의 뒤로 → 달력 취소, 날짜·시각 최종 확인, 초 선택, 저장·재조회·다른 필드 수정 시 시각 보존, 시각 수정, 시간순 내역을 검사했습니다.
- 새 입력·복사·즐겨찾기·반복 확인은 현재 시각을 사용합니다. 해지·배분 연결 거래는 하나의 시각을 공유하며 이동 전체 수정 시 함께 바뀝니다.
- 빈 시간·HH:mm·HH:mm:ss·엑셀 시간 값·날짜/시간 결합 셀·1900/1904 날짜 체계를 읽습니다. 잘못된 시각·수식·엑셀 오류는 거절합니다. 시각이 다른 동일 금액 기록과 중복/ID 충돌을 구분합니다.
- XLSX/ZIP 시간 왕복, 시간 없는 이전 양식·SMV1/2/3·ZIP1/2 호환, SMV4/ZIP3 저장, 기존 합계·자산 계산을 확인했습니다. 전체 기존 기능 검사도 실행했습니다.
