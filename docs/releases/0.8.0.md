## 보관 APK에서 확인한 기능

- DB4에서 `저축회수`를 처리합니다. 회수는 수입에 더하지 않고 저축 합계에서 빼며 사용 가능 금액에 돌려놓습니다.
- 저축 해지·배분에서 원금·실제 수령액·예금/투자 배분을 입력하고, 이자 수입·순저축·투자·사용 가능 변화를 반영합니다. 당시 방식은 현재0.8.3 이후의 기초자산/실제 원금 분리 방식과 구분합니다.
- 생성된 연결 거래를 수정하면 이동 전체 수정으로 엽니다. 이 분기는 실제 보관0.8.0 APK에 이미 존재합니다. 앞선 이력 문서에서0.8.1의 변경으로 소개했지만, 최초 도입 버전을 문서만으로 단정할 수 없어 이번에 확인한 사실을 기록합니다.
- 일반 새 기록의 돈의 성격은 수입·지출·저축·투자 네 가지입니다. 저축회수 직접 입력 선택지는0.8.2에서 추가됩니다. 기존 회수 내역의 전용 수정 처리는 포함됩니다.
- 저축회수의 XLSX/계획 ZIP 처리와 순저축 통계, 회수로 음수가 된 분류의 원형 비중 제외를 지원합니다. 반복 예정만으로 실제 합계가 늘지 않습니다.
- 기초자산 기능은0.8.3 이후입니다. 후속 보관 소스의 모은 비율·추가 배분율 표시를0.8.0 기능으로 넣지 않았습니다.

## 복구 방법과 의미

APK에는 실행 코드와 리소스가 있으므로 동작하는 소스를 재구성할 수 있지만, 주석·원래 파일 작성 과정·일부 변수명 등을 그대로 추출하는 것은 아닙니다. 이번에는 새 디컴파일러나 앱 라이브러리 설치 없이, 앞뒤 보관 소스를 APK와 대조해 재구성했습니다.

1. `v0.8.1` 공개 보관 소스와 별도 로컬 원본 보관본을 기준으로0.8.0/code14를 설정했습니다.
2. APK에 없는 후속 비율 계산/표시를 분리하고, 당시 통계 제목·엑셀 요약과 연결 편집 분기를 APK 기준으로 맞췄습니다.
3. JDK17/API36/Build Tools36으로 빌드하고 APK의 내부 파일과 DEX 함수별 명령을 비교했습니다.

확인에 사용한 원본 APK는 패키지`kr.chagok.ledger`, versionName`0.8.0`, versionCode`14`입니다. 단순히 파일 이름만 보고 버전을 판단하지 않았습니다.

## 이번 검증
